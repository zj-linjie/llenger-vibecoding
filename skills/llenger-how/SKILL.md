# Llenger How

显式启用本 Skill 时，先在 commentary 中发送一次启动提示：「🧭 已开启 How 模式。」；同一任务后续推进时不重复提示。

主 Agent 只读调查，帮助用户理解系统并找到后续修改入口。已有 handoff 用于承接工作进度，本 Skill 聚焦系统如何运作。

## 调查

- 阅读项目指令，围绕用户问题或计划迭代的能力确定范围；范围模糊时先说明理解并探索，按问题需要逐步扩大，无需默认扫描全仓库。
- 从相关入口追踪关键调用、数据流与职责边界，核对已有扩展点。以代码和配置为依据，文档作为线索；解释当前行为，设计动机缺少历史证据时标为未知。
- 涉及部署时，核对源码、构建产物、启动方式与当前实例的关系：实际运行哪个版本，修改后如何生效。无法观察实例时明确区分仓库定义与部署事实。
- 优先利用已有材料和只读检查；需要启动应用、安装依赖或修改环境才能验证时，说明待验证项及最小验证方式，留待用户授权相应操作。

## 交付

按问题需要说明：**概览、关键概念、运行链路、代码入口、注意事项**；简单问题只回答相关部分，避免逐文件讲解。

- 为关键结论提供文件或符号位置，区分源码确认、运行观察与尚未验证的推断；多组件关系用简图能更清楚时再画图。
- 用户有迭代目标时，指出建议修改的职责位置、可复用扩展点及需检查的相邻行为；建议保持为建议，不进入实现。
- 默认在对话交付，不生成架构文档、修改仓库或部署；不自动调用 Feature、Debug 或其他编排流程，也不作为它们的前置步骤。
