# Llenger Agents

主 Agent 为目标项目整理一份简短、可核查的 `AGENTS.md`，让后续会话知道项目里哪些做法需要遵守、改动后怎么验证。

## 确定文件和操作

- 默认定位到目标 Git 仓库根目录。新项目未初始化 Git 时，使用用户指定的项目目录或当前目录。用户指定子项目时，将范围限定在该子项目。
- 先读目标位置已有的指令和适用的上层规则。用户要求生成或更新时写入目标文件，要求检查或只调用 Skill 时，在对话中给出建议。目标默认是项目 `AGENTS.md`。同目录有非空的 `AGENTS.override.md` 时，先说明哪个文件生效，由用户指定更新目标。
- 写入前确认文件的实际路径位于目标项目内。目标文件已存在时按更新处理。

## 提炼项目约定

- 从用户已确认的要求、README、任务脚本、构建或 CI 配置开始，按需核对关键入口和目录。对新项目，只写已经确定的做法，命令和结构随项目落地再补。
- 优先写会影响下一次改动的内容。可选内容包括容易找错的入口、项目实际采用的验证命令及运行目录、已有调用方依赖的行为、校验位置或其他关键约束。详细设计引用已有文档，并注明什么任务需要阅读。
- 新增每一条前，判断它能防止哪种改错、找错或验错。用项目特有的做法补充上层规则，已有的通用规则避免复述。
- 更新时保留仍有效的约束和原有组织，合并重复条目。能证实过时的命令或路径就修正。遇到可能是有意保留的约定与实现冲突时，保留原约定并说明冲突。

## 交付

读回目标文件并检查改动。依据仓库核对新增的命令、路径和文档引用，确保每条规则都有具体用途。先说明生成或更新了什么，再列关键依据和仍待确认的事项。
