# Llenger Clean

排查磁盘空间、开发构建产物和工具缓存。先只读调查并展示具体候选项；只有用户确认要清理的文件或目录，才执行清理。明确保留用户排除的内容。

## 1. 只读调查

- 按用户指定范围检查磁盘可用空间及占用最大的目录；报告权限、扫描范围和共享空间等导致的统计限制，不把占用量直接等同于可回收空间。
- 对候选项列出完整路径、大小、归属项目或工具、判断依据、清理影响及不确定性。区分可重建的构建产物、依赖、工具缓存、应用数据、备份和用户文件；检查目录内容，不能仅凭 `target`、`build`、`cache` 或 Git 忽略规则认定整个目录可删除。
- 特别留意构建目录中混放的安装包、备份、签名产物及用户文件；拆分到可以分别确认的子目录。用户要求保留的内容从候选项排除。
- 检查相关构建、应用和缓存是否正在使用。若存在占用或用途不明，说明证据和影响，暂不将其视为可安全清理；不强制终止进程或绕过锁。

## 2. 确认后清理

- 清理是硬性确认边界：执行删除、清空、卸载或可能移除文件的清理命令前，先展示每个待清理文件或目录的具体路径和影响，等待用户明确确认这些对象。一般的“清理缓存”指令、静默或时间流逝都不构成对具体对象的确认。
- 已在当前会话中明确确认具体路径或清单项目时，可在其授权范围内执行，无需重复确认。用户确认部分项目时只处理该部分；新增候选、范围扩大或对象发生实质变化时重新展示并确认。
- 确认后重新检查目标路径、类型及占用状态，只操作确认的对象；优先使用对应工具支持的定向清理方式，并核实命令不会清理额外对象。锁定或正在使用的项目暂缓，告知用户。
- 不删除项目源码、备份、个人文件、应用数据或已排除内容，除非这些具体对象已列出并由用户明确确认。

## 3. 核验与交付

- 检查确认对象的实际清理结果及磁盘可用空间变化，说明重建、重新下载或恢复能力的影响。报告已清理、未清理及失败项目和原因；空间变化与目录大小可能不同。
