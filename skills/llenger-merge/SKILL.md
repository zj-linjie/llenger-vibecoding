# Llenger Merge

显式启用本 Skill 时，先在 commentary 中发送一次启动提示：「🔀 已开启 Merge 模式。」；同一任务后续推进时不重复提示。

由主 Agent 推进。用户仅要求评估时止于只读调查；merge、提交、推送、发布与装机按会话已有授权执行。

## 1. Preflight · 先查上游

- 阅读项目指令，确认 fork、上游 remote、目标 ref、当前分支及工作树状态，记录合并前 SHA；保留已有改动，必要时在隔离 worktree 操作。
- 检查目标版本的 release、近期相关 issues/PRs 与回滚记录，关注 crash / hang / deadlock / revert / regression；包括已关闭但影响该版本的条目。发现相关信号时，附链接和影响，暂停合并，交用户决定继续、换版本或等待；查不到时明确预检未完成。
- 从目标项目文档读取验证入口、已知失败清单、版本与更新规则、构建环境配方；缺失项从代码和 CI 核实，仅询问无法查明且影响执行的选择。数据留在目标项目文档，本 Skill 不维护环境清单。

## 2. Merge · 固定范围

- 获取并固定上游目标 SHA，保留合并前基线；按项目约定合并。结合两侧改动解决冲突，保护 fork 的定制行为；产品取舍无法由需求判定时交用户决定。
- 用合并前 SHA 与目标 SHA 的差异及合并结果确定影响范围，同时检查无文本冲突的接口、配置和依赖变化；完成条件是冲突已解决、差异可解释。

## 3. Verify · 分层验证

- 查阅目标版本的 CI，执行对应检查及 fork 自有必需检查；TS/Rust 项目覆盖类型检查、单元测试与 Cargo 测试，命令从项目读取。上游发布或 CI 通过不代表真实使用路径已验证。
- 浏览器验证按 diff 选择改动的 spec，并映射业务代码、共享依赖和冲突处理影响到的场景；仅匹配 spec 文件名会漏测。默认单 worker（Playwright 使用 `--workers=1`），运行必要冒烟；不默认启动全量浏览器套件。
- 记录命令、版本及结果。出现成片失败时先暂停批量执行，转入归因；避免继续扩并发或反复全量重跑。

## 4. Attribute · 对照归因

- 对失败用相同配置单独重跑；再在合并前 SHA 的隔离 worktree 中，用相同测试、输入、环境与依赖安装方式对照。测试为新增时，确认能在旧基线运行；无法对照则保留未定结论。
- 合并后稳定失败、基线通过：作为合并引入或带入的回归，追溯上游与冲突修改；浏览器回归实锤时报告证据，交用户决定修复、排除相关提交或换版本。
- 两边同样失败：说明是既存问题或环境问题，继续用证据区分；单次重跑通过仅说明存在不稳定性。已知 flaky 必须匹配项目清单中的条件与证据，才可按该清单处理；未归因失败保留为未解决，不计通过。

## 5. Ship · 验证实际产物

- 检查通过或剩余问题已有明确处置后，按项目文档核对版本号与更新器比较规则；发布或装机前重新查官方最新版本。撞号时暂停交用户决定，按项目规则跳号后重新构建。
- 获准构建与装机时，使用项目环境配方，验证产物版本、签名及所需环境配置是否实际进入构建；报告只列配置键与验证结论，隐藏凭据。装机保留可恢复的旧产物，确认运行实例来自新构建并完成关键路径冒烟。
- 交付合入的 SHA、验证结果、失败归因、未覆盖项，以及实际构建和安装状态。仅完成源码合并时按该范围交付，不声称装机或发布完成。
